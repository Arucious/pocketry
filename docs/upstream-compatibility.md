# Upstream compatibility validation

Verified locally on 2026-10-11 against upstream `main` at
`8146b250206b5411327f32adecbbe0d0c2bc05a9`, using Node.js 22.23.3 and npm 10.9.9.
A fresh fetch confirmed that this remains upstream's current `main`.

migration, persistence, library/history behavior, primitive drawing and mobile
controls.

## Geometry comparisons

`scripts/fixtures/upstream-empty-bins.json` records references generated by the
upstream builder and serializers, using its export resolution. The permanent
`scripts/lib/legacy-export.test.ts` starts the real fork CLI in a separate Node
process and compares these references:

| Case | Bin | Fill / lip | Triangles |
| --- | --- | --- | --- |
| Default command | 2 × 3 × 6 | Hollow / standard | 8,064 |
| Small | 1 × 1 × 2 | Hollow / standard | 5,230 |
| Long | 4 × 1 × 6 | Hollow / standard | 6,932 |
| Solid | 2 × 3 × 6 | Solid / standard | 7,726 |
| Solid without lip | 4 × 2 × 3 | Solid / none | 5,102 |
| Hollow without lip | 2 × 1 × 3 | Hollow / none | 1,688 |

All six STL payloads match byte-for-byte after the descriptive 80-byte header.
All six 3MF mesh XML blocks match exactly, including vertices and triangles.
The CLI retains original filenames, defaults, option syntax and millimetre
units. The tests also check nonzero exits with no artifacts for invalid requests.
Comparison of the old parser exposed another compatibility gap: the new parser
rejected repeated legacy flags/dimensions that originally used the last supplied
value. Empty-bin mode now preserves that behavior, including the final output
directory; new SVG/project modes retain strict duplicate checks. Unit and real
CLI regressions cover the restored behavior.

The STL header and 3MF title/object names differ from the old CLI, and an
editable `.pocketry.json` backup is now added. Those differences are deliberately
excluded from geometry comparison; whole-file equality is not claimed.

The upstream CLI itself fails under plain Node in this environment while
loading a Vite-only WASM import. That failure reproduces in the clean baseline.
Reference generation therefore uses Vitest's supported loader with unchanged
upstream production modules. The fork CLI succeeds after the runtime import
boundary fix. No baseline geometry algorithm was patched to obtain references.

## Saved-project and library schema comparisons

A second clean archive of the same upstream commit used its original lockfile
and Zod 3.23.8. A generic adapter exercised that checkout and the fork with Zod
3.25.76 against 35 cases: all 16 standalone bundled samples, two historical
project fixtures, all 16 projects in the sample library, and its library backup
envelope. Project input versions 9, 16, 19, 24, 31, 32, 35 and 36 were covered,
as well as library version 1.

Every case passed migration/schema validation, deterministic repeated parsing,
serialization and reparse checks. All parsed and serialized hashes, and all full
normalized snapshots, matched between upstream and fork. Canonicalization only
sorts JSON object keys and applies normal JSON omission of undefined object
fields; arrays, IDs and every serialized value remain intact. The library
comparison additionally preserves project ordering and the complete envelope.
No schema output drift was found in this corpus.

The upstream-generated hashes are committed in
`shared/gridfinity/fixtures/upstream-sample-migrations.json`; the permanent
`shared/gridfinity/upstream-sample-migrations.test.ts` adds 35 regression cases.
It checks original source hashes before comparing migrations and portable
serialization against these references. The adapter in
`scripts/fixtures/upstream-migration-reference.test.ts.txt` reproduces evidence
without changing upstream production code. Full snapshots and lockfile/runtime
provenance remain local under `exports/compatibility/sample-migrations/`.

## Reproducing the references

From the fork checkout, with Node.js 22 selected:

```sh
taskForkDir="$PWD"
taskBaselineCommit=8146b250206b5411327f32adecbbe0d0c2bc05a9
taskBaselineDir=$(mktemp -d)
git archive "$taskBaselineCommit" | tar -x -C "$taskBaselineDir"
(
  cd "$taskBaselineDir"
  npm ci && npm run check && npm test -- --maxWorkers=4 --testTimeout=30000 && npm run build
)
cp -f "$taskForkDir/scripts/fixtures/upstream-reference.test.ts.txt" \
  "$taskBaselineDir/client/src/lib/gridfinity/upstream-reference.test.ts"
(
  cd "$taskBaselineDir"
  POCKETRY_REFERENCE_INPUTS="$taskForkDir/scripts/fixtures/upstream-empty-bins.json" \
  POCKETRY_REFERENCE_DIR="$taskForkDir/exports/compatibility/reproduced" \
  POCKETRY_REFERENCE_COMMIT="$taskBaselineCommit" \
  npm test -- --maxWorkers=1 client/src/lib/gridfinity/upstream-reference.test.ts
)
diff -u scripts/fixtures/upstream-empty-bins.json exports/compatibility/reproduced/reference.json
npm test -- --maxWorkers=2 scripts/lib/legacy-export.test.ts
cp -f "$taskForkDir/scripts/fixtures/upstream-migration-reference.test.ts.txt" \
  "$taskBaselineDir/shared/gridfinity/upstream-migration-reference.test.ts"
(
  cd "$taskBaselineDir"
  POCKETRY_MIGRATION_REPORT_DIR="$taskForkDir/exports/compatibility/reproduced-migrations" \
  POCKETRY_MIGRATION_GOLDENS="$taskForkDir/shared/gridfinity/fixtures/upstream-sample-migrations.json" \
  npm test -- --maxWorkers=1 shared/gridfinity/upstream-migration-reference.test.ts
)
npm test -- --maxWorkers=2 shared/gridfinity/upstream-sample-migrations.test.ts
```

The adapter only adds a temporary test to the extracted snapshot. Its regenerated
reference JSON was confirmed identical to the committed fixture. Do not regenerate
goldens from the fork just to make a failure pass. A deliberate kernel or export
format change requires reviewing fresh baseline artifacts before updating them.

## Additional findings and limits

Review caught a mismatch in the new saved-project headless exporter: text with
an inherited color used the stored rim color even when rim coloring was off.
The exporter now inherits the body color in that case, matching the browser.
Its regression failed before the fix and passes afterward. Explicit text colors
and saved material/project round trips remain covered.

The main production JavaScript bundle increases from 3,252,936 to 3,342,493 bytes.
Using the same gzip encoder, compressed size increases from 966,732 to 997,488
bytes, about 31 KB. SVG parsing is eagerly imported by the new dialog. The
existing large-chunk build advisory appears in both versions; this measurement
does not establish startup latency on a slow device.

Dependency review confirmed that React 18.3.1, Vite 5.4.21, Three 0.180.0,
fflate 0.8.3, the application server's Express 4.21.2 and Manifold 3.5.1 remain
unchanged. The main shared changes are Zod 3.23.8 → 3.25.76 and fast-xml-parser
5.10.1 → 5.11.2; the latter also changes Manifold's existing transitive XML
parser. The MCP SDK has a nested Express 5 dependency, while the application
server still resolves Express 4. Shared proxy-addr moves from 2.0.7 to 2.0.8.
Original geometry, migration and font-source tests passed with these changes;
no concrete incompatibility was found in the exercised paths.

The new headless project reader's documented 10 MB cap can reject a portable-font
project that the original browser accepts. Projects without saved appearance
export as a single uncolored 3MF through the headless wrapper; explicit saved
materials enable its material regions. Those are wrapper policies, not changes
to original browser import/export behavior. Nozzle fit and physical printing
are outside this compatibility check.

Before an upstream submission, repeat validation if upstream advances, check
Linux/Windows portability and the Firefox raster-to-bin workflow. Review
startup latency on a slow device alongside the dependency and bundle-size
tradeoffs. Omit the fork-specific commit-author policy change from an upstream
PR. These results provide regression evidence;
they cannot prove the absence of every possible bug.
